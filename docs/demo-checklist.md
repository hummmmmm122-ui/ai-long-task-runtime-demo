# 录屏前检查清单

这份清单用于正式录制或现场演示前 3 分钟快速确认，目标是避免页面打不开、路径点错、状态残留或讲述节奏混乱。

## 1. 页面与网络

- 打开在线演示地址：
  `https://hummmmmm122-ui.github.io/ai-long-task-runtime-demo/`
- 确认首屏标题是 `Workflow Workbench`。
- 确认默认节点是 `生成方案`，导演提示是 `01 观察等待`。
- 如果线上页面打不开，切换本地备用方案：
  ```bash
  npm install
  npm run dev
  ```

## 2. 录屏窗口

- 建议浏览器窗口比例：16:9。
- 推荐分辨率：`1366 x 768` 或 `1920 x 1080`。
- 浏览器缩放建议：`100%`。
- 录屏前关闭无关标签页、通知弹窗和下载栏。

## 3. 演示点击路径

按这个顺序点击，避免状态跳乱：

1. 停留默认页面，讲 `01 观察等待`。
2. 点击 `采纳到当前节点`，确认右侧出现“偏好已并入”反馈。
3. 点击 `保留并开分支`，确认页面出现 `V2 分支` 反馈。
4. 点击顶部 `推进演示`，进入 `采纳修改` 节点。
5. 再点击一次 `推进演示`，进入 `交付建议`，确认右上卡片显示 `READY`。
6. 如需重录，点击 `重置`，确认状态回到 `01 观察等待`、`等待确认`、`未开启`。

## 4. 口播材料

- 开场前先看 [演示导览图](demo-map.md)，确认主线。
- 录屏时跟随 [2 分钟口播脚本](demo-script.md)，不要临场扩展太多。
- 重点反复强调三个关键词：`已接收`、`处理中`、`可介入`。

## 5. 备用话术

如果观众问“这是不是只是 loading 动画”，可以回答：

> 不是。这个 demo 的重点不是动画，而是把 AI 长任务拆成可观察的节点，并允许用户在等待中继续反馈、修改和开启分支。

如果观众问“为什么没有真实 AI 后端”，可以回答：

> 这是一个交互验证 demo，先验证长任务等待态的产品形态。真实后端可以后续接入任务事件流，把节点状态替换成真实运行数据。

## 6. 最终确认

- 页面能打开。
- 关键路径能点通。
- 完成态显示 `READY`。
- README、导览图、口播脚本、检查清单都已在仓库中。
- GitHub Actions 最近一次 Pages 部署为绿色。
